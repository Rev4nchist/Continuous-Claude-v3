# Cross-Session Coordination — Next-Evolution Proposal (2026-08-04)

## 1. Where CCv3 is today

The substrate is live and substantially hardened since the 2026-06-28 review that first named its gaps ([CURRENT-STATE.md:15-23](../../system-update/CURRENT-STATE.md)):

- **Identity is fixed.** `resolveSessionId()` prefers the hook-payload session id — the only id all hooks agree on, verified by probe 2026-07-26 — ending the two-rows-per-session split that left 0 of 8,179 claims owned by a live-looking session (`.claude/hooks/src/shared/session-id.ts:133-156`). `canonicalProject()` erases path-spelling splits (one repo was two keys covering 5,737 rows) and worktree splits, via `git rev-parse --git-common-dir` (`session-id.ts:158-205`).
- **Claims are atomic and fenced.** `resolveFileClaim` is a single `INSERT ... ON CONFLICT DO UPDATE ... WHERE` statement that decides, claims, and logs in one transaction — closing the check-then-claim race where two sessions were both told to proceed (`.claude/hooks/src/shared/db-utils-pg.ts:589-766`). Every change of custody mints a monotonic fence from `coordination_fence_seq`; renewals keep their generation (`db-utils-pg.ts:707-711`).
- **Reclamation is two-condition.** A claim is taken over only when the lease has expired AND the holder's heartbeat is stale — an idle-but-alive session is never preempted (`.claude/hooks/src/file-claims.ts:17-19,141-144`; rationale in `.claude/hooks/src/shared/leases.ts:12-22`). Leases are class-based: 10 min for ordinary files, 60 min for harness source, because two sessions editing `~/.claude/hooks` produce a machine running a mix of half-applied changes (`leases.ts:24-51`).
- **Failure is visible.** Break-glass override writes a distinct `claim_break_glass` event (`file-claims.ts:22-34`); a DB outage yields an explicit "conflict NOT checked" warning instead of silently reading as healthy (`file-claims.ts:169-179`).
- **A verification harness exists.** Seven probe scripts gate the layer (`scripts/coordination/`: `load-probe.mjs`, `lease-probe.mjs`, `session-lifecycle-probe.mjs`, `lane-race-probe.mjs`, `claim-sql-probe.mjs`, `degradation-probe.mjs`, `event-recording-probe.mjs`), plus `liveness-predicate-guard.mjs` enforcing the `GREATEST(last_heartbeat, last_activity_at)` liveness rule (`.claude/rules/cross-terminal-db.md`). A lane board (`scripts/coordination/lane.mjs`) coordinates work-item claims above the file level.

**Known limitations** (all previously named in [BACKLOG.md Tier 2b](../../system-update/BACKLOG.md), verified still open):

1. **Intra-session fan-out is invisible** — subagents share the parent's `session_id`, so the lock layer cannot see two of one session's own parallel agents colliding on a file (MS-01, `BACKLOG.md:82`).
2. **Sync and git writes bypass the lock** — `file-claims` gates only the Edit/Write tools; the Hook Source Regression clobbered shared hook files via the sync script (MS-02, `BACKLOG.md:83`).
3. **Git-index and build operations are unserialized** — concurrent sessions race `.git/index.lock` (MS-03, `BACKLOG.md:84`); `git-safe.ps1` retries around the MSYS crash but nothing queues the underlying contention.

## 2. Frontier scan

All external claims below were re-verified directly against the cited page during this run (WebFetch of each abstract/doc page), per the citation self-audit.

**Shipped harnesses converged on isolation, not locking.** Claude Code itself now ships first-class worktree support: `--worktree` per session, and per-subagent isolation via `isolation: worktree` in agent frontmatter — each subagent gets a temporary worktree, auto-removed when unchanged, protected by `git worktree lock` while running, with `worktree.baseRef: "head"` to branch from in-progress work ([code.claude.com/docs/en/worktrees](https://code.claude.com/docs/en/worktrees)). Subagent worktree isolation is opt-in — the documented default leaves parallel subagents in the shared tree, which is exactly CCv3's MS-01 gap. GitHub's Copilot coding agent runs in a GitHub Actions-powered environment and "can only push to branches it created" ([github.blog](https://github.blog/news-insights/product-news/github-copilot-meet-the-new-coding-agent/)) — isolation by VM + branch scoping. (Oracle-stage reporting also placed OpenAI Codex and Google Jules in the container/VM-per-task camp; those two pages were not re-fetched in this run's audit, so treat the specifics as secondary.)

**The 2026 literature says isolation-then-merge is not solved.** AgenticFlict measured 142K+ agentic PRs from 59K+ repos and found a **27.67% merge-conflict rate**, extracting 336K+ fine-grained conflict regions ([arXiv:2604.03551](https://arxiv.org/abs/2604.03551), AIware 2026). STORM states the critique directly: workspace isolation "defers conflict resolution to a post-hoc merge step where recovery is expensive," and instead mediates a shared workspace so "conflicting edits are detected and resolved at write time" — beating a git-worktree multi-agent baseline by +18.7 on Commit0-Lite ([arXiv:2605.20563](https://arxiv.org/abs/2605.20563)). That is CCv3's design premise, published as a 2026 research position.

**But classical pessimistic locking is also under attack.** CoAgent argues locks and OCC both fit LLM agents poorly — "Locks block long inference intervals; OCC abort-and-retry discards minutes of work on every conflict" — and proposes MTPO: fix a serialization order at launch, apply writes speculatively, notify affected agents to repair, with saga-style inverses registered per tool ([arXiv:2606.15376](https://arxiv.org/abs/2606.15376)). CAID (CMU, w/ Graham Neubig) proposes centralized delegation + asynchronous execution + isolated workspaces, improving over single-agent baselines by +25.6% absolute on PaperBench and +14.7% on Commit0 ([arXiv:2603.21489](https://arxiv.org/abs/2603.21489)) — evidence that a central delegator assigning disjoint work (what CCv3's proactive-delegation rule does manually) measurably outperforms uncoordinated fan-out.

**CRDTs don't rescue anyone.** CodeCRDT achieved 100% structural convergence with zero merge failures — and still measured a **5–10% semantic conflict rate**, with per-task outcomes ranging from +21.1% speedup to −39.4% slowdown ([arXiv:2510.18893](https://arxiv.org/abs/2510.18893)). Structural merge ≠ semantic correctness.

**Identity/provenance is standardizing at the observability layer, not the coordination layer.** OpenTelemetry's registry defines `gen_ai.agent.id`, `gen_ai.agent.name`, and `gen_ai.conversation.id` ("unique identifier for a conversation (session, thread)") — though all three are currently marked deprecated on the registry page, having moved to the dedicated GenAI semconv repository, i.e. the convention is active but in flux ([opentelemetry.io registry](https://opentelemetry.io/docs/specs/semconv/registry/attributes/gen-ai/)). Git-trailer attribution remains an unsettled convention war (`Co-authored-by` vs `Assisted-by` vs proposed `Generated-By`) per secondary sources ([baristalabs.io](https://www.baristalabs.io/blog/ai-assisted-commits-need-provenance-trailer) — blog, not independently re-verified; treat as directional).

**Fencing tokens for agent file coordination appear to be whitespace.** No surveyed harness ships fenced takeover of stale claims as a first-class primitive; the pattern lives in general distributed-systems practice (ZooKeeper/etcd/Kafka epochs). This is an absence-of-evidence finding from one bounded survey, not a proven negative — but on this axis CCv3 appears **ahead** of shipped products.

## 4. Recommendations

1. **ADOPT — Close MS-01 with native subagent worktree isolation instead of extending the lock table.** The original MS-01 plan keys claims by `(file_path, project, session_id, agent_id)` (`BACKLOG.md:82`). Claude Code now ships the structural alternative: `isolation: worktree` frontmatter per subagent, with automatic sweep, `git worktree lock` during runs, and `worktree.baseRef: "head"` for in-progress work ([worktrees doc](https://code.claude.com/docs/en/worktrees)). This solves fan-out collisions by construction, matches the direction every shipped harness took, and our `canonicalProject()` already maps worktree claims to the main repo's key (`session-id.ts:170-177`) so cross-*session* locking still works from inside a worktree. Reserve worktree isolation for parallel *implementation* agents (spark/kraken-style mechanical fan-out); read-only agents (scout, critic) don't need it. Keep the lock layer as the shared-tree safety net — AgenticFlict's 27.67% conflict rate is the argument for not moving *everything* to isolation-then-merge.
2. **ADOPT (reconfirm, ship first) — MS-02 sync-script claim-awareness.** The frontier adds urgency, not novelty: CoAgent and the fencing literature both identify the unguarded second writer as the failure that voids any lock guarantee, and CCv3 has a documented incident (Hook Source Regression) through exactly this path. `BACKLOG.md:83` already ranks it "ship first (highest blast radius)". Nothing external changes the design; this proposal simply re-verifies it as the top item.
3. **ADOPT (reconfirm) — MS-03 git/build serialization via Postgres advisory lock on the repo key.** No surveyed harness solves shared-tree git contention (they sidestep it), so there is nothing to copy — but the natural extension of our own lease pattern (`leases.ts:32-38` already reserves the `git-index:`/`build:` classes as deliberately-absent) plus a `pg_advisory_lock` keyed on `canonicalProject()` fits the existing transport. Integrate with `git-safe.ps1` so the retry wrapper and the queue are one mechanism, not two.
4. **WATCH — CoAgent-style advisory-notify + agent repair for ordinary project files.** MTPO's "runtime informs, agent repairs" ([arXiv:2606.15376](https://arxiv.org/abs/2606.15376)) suggests a softer posture than hard-deny for low-stakes conflicts: allow the edit, inject a conflict notice, let the model reconcile. CCv3's hybrid posture table (`BACKLOG.md:86`) already points this way (warn project / block infra). Research-grade today — no reference implementation to borrow; revisit once MS-02/03 land and the block-rate telemetry shows whether hard blocks are actually costing throughput.
5. **WATCH — OTel GenAI identity conventions.** `gen_ai.agent.id` / `gen_ai.conversation.id` are the emerging names for what `sessions.id` already is, but the attributes just moved repositories and are marked deprecated at their old location ([registry](https://opentelemetry.io/docs/specs/semconv/registry/attributes/gen-ai/)). Nothing to build now; align column/telemetry naming opportunistically the next time the `sessions` schema or Braintrust span metadata is touched.
6. **SKIP — CRDT-based file merging.** CodeCRDT's own numbers (5–10% semantic conflicts despite 100% structural convergence, −39.4% worst-case slowdown, [arXiv:2510.18893](https://arxiv.org/abs/2510.18893)) show CRDTs replace a visible conflict with an invisible one. Wrong fit for a harness whose core lesson is "make failure visible."
7. **SKIP — abandoning the pessimistic lock layer for isolation-everywhere.** The measured 27.67% agentic-PR conflict rate ([arXiv:2604.03551](https://arxiv.org/abs/2604.03551)) and STORM's write-time-mediation results ([arXiv:2605.20563](https://arxiv.org/abs/2605.20563)) both vindicate keeping write-time prevention for shared-tree work. The lock layer is a differentiator, not legacy.

## 5. Integration approach

- **MS-01 reframe (rec 1):** add `isolation: worktree` to the frontmatter of parallel-implementation agents in `.claude/agents/` (candidate: a worktree-variant of `spark` for the "N parallel sparks, one file each" pattern in `.claude/rules/proactive-delegation.md`); update that rule's fan-out guidance; add a `.worktreeinclude` if worktree-spawned agents need env files. Set `worktree.baseRef: "head"` in settings so subagent worktrees branch from in-progress work, not the default branch — with the default `"fresh"` base a subagent would silently work against `main` ([worktrees doc](https://code.claude.com/docs/en/worktrees)). Effort: small (config + rule text + one probe). Risk: merge burden shifts to the orchestrator (mitigate: worktree agents only for disjoint-file tasks, which is already the rule); Windows worktree-removal symlink/junction behavior needs the fixed Claude Code version (doc notes v2.1.205+); reuse the confirmed-clean-only GC discipline from `.claude/rules/codex-worker-safety.md`. What could go wrong: a worktree agent commits (racing `.git/index.lock` with the parent — shared `.git` directory) → keep the "agents don't commit; orchestrator commits" convention, which MS-03 then serializes.
- **MS-02 (rec 2):** unchanged from `BACKLOG.md:83` — make `scripts/sync-to-active.sh` claim-aware and hard-block cross-session writes to the infra set regardless of path. This proposal adds no new design, only priority confirmation.
- **MS-03 (rec 3):** implement the reserved `git-index:`/`build:` lease classes (`leases.ts:32-38`) as `pg_advisory_lock(hashtext(canonicalProject()))` acquired in `git-safe.ps1` and the hook build path; reuse `scripts/coordination/` probe conventions for the gate. Effort: medium. Risk: a hung holder blocks all committers → bound with `pg_try_advisory_lock` + timeout + the existing break-glass pattern.
- **Backlog ties:** ST-02 (done — foundation this all sits on), MS-01/MS-02/MS-03 (Tier 2b), SG-04 gating unchanged. Rec 4's telemetry prerequisite ties to the event-recording probe and the `claim_blocked`/`claim_degraded` counters (the memory note that `claim_degraded` was never emitted should be re-checked against the current `resolveFileClaim` before building on it).

## 6. Benefits

- **Parallel implementation waves without manual choreography.** Today multi-agent builds rely on hand-assigned disjoint files (Wave 1 pattern, `CURRENT-STATE.md:20`). Worktree-isolated subagents make same-session collisions structurally impossible, so Dave can fan out N sparks without the orchestrator being the only safety mechanism — the measured upside of coordinated delegation is +14.7–25.6% task accuracy in CAID's benchmarks ([arXiv:2603.21489](https://arxiv.org/abs/2603.21489)).
- **Fewer lost-work incidents.** MS-02 closes the path that caused the Hook Source Regression; MS-03 removes the `.git/index.lock` races that have blocked commits in live sessions (`BACKLOG.md:84`). Both convert "re-do the work after a clobber" into "wait a few seconds in a queue."
- **Keeps the differentiator.** The fenced, visible, two-condition lock layer is ahead of anything shipped; these changes extend it to the two writer paths it doesn't cover instead of replacing it with the herd's isolation-then-merge — which measurably fails ~1 in 4 times at merge ([arXiv:2604.03551](https://arxiv.org/abs/2604.03551)).
- **Cheap wins now, options later.** Recs 1–3 are config + one advisory lock; the WATCH items (advisory-repair posture, OTel naming) cost nothing until their ecosystems stabilize.
