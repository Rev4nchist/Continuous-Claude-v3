Zero injections in 415 fires, including 287 fires since 2026-07-01. **The maximum score ever observed on this path (0.0203) is 2.5× below its own floor (0.05).** The filter at `agent-recall-injector.ts:389` (`r.score >= PROACTIVE_INJECTION_FLOOR`) therefore cannot pass anything.

Root cause, two compounding parts:

1. **A scale mismatch the sibling hook already fixed.** `memory-awareness.ts:49-50` splits the floor by mode — `TEXT_ONLY_FLOOR = 0.05` ("FTS ts_rank scores: 0.05-0.5 typical") and `HYBRID_FLOOR = 0.01` ("RRF fused scores: 0.01-0.03 typical"). `agent-recall-injector.ts:56` still carries the single pre-split constant, and its own comment at `:14` — "Applies the same `PROACTIVE_INJECTION_FLOOR = 0.05` as memory-awareness" — is now false, because `memory-awareness` no longer has that constant.
2. **Decay is applied before the comparison.** In text-only mode `recall_learnings.py` inlines the decay multiplier into SQL (`ts_rank(...) * decay_weight`, `opc/scripts/core/recall_learnings.py:595-607`), and the hook passes no `--no-decay`. So a floor calibrated on *raw* ts_rank (0.05–0.5) is compared against a *decayed* score. This is the same defect class as `D3b-01`, which `CURRENT-STATE.md:31` names as a co-dominant memory suppressor on the main path.

**Routing, measured.** The same log is a spawn census (unbiased except for documented skips: `oracle` and `pathfinder` are excluded by `SKIP_SUBAGENTS`, `agent-recall-injector.ts:62`, so their zero counts are an artifact, not disuse).

- 415 spawns across **18 distinct agent types**. The live selection surface is **~51** agent types (37 repo `.md` + built-ins + plugin agents + archive leakage), so roughly two-thirds of the roster was never selected in three months.
- Head-heavy: `scout` 141 (34.0%), `Explore` 67 (16.1%), `kraken` 58 (14.0%), `codex-adversary` 57 (13.7%) = **77.8% in four agents**.

Share of spawns: 16.1% lifetime → 18.1% since 07-01 → **28.9% since 08-01** (11 of 38). Last used 2026-08-07. `Explore` is a **built-in** subagent ([Agent SDK docs](https://code.claude.com/docs/en/agent-sdk/subagents)), so it cannot be removed by pruning files. *(The rule's stated rationale — that Explore uses Haiku — I could not verify; treat that rationale as unconfirmed. The usage figures are measured.)*

**Roster hygiene defects (new, verified).** Agent identity comes from the frontmatter `name:`, not the filename, and `~/.claude/agents/archive/` is still discovered:

## 2. Frontier scan

1. **Routing degrades measurably with roster size — and there is a cheap fix.** *Scaling Enterprise Agent Routing: Degradation, Diagnosis, and Recovery* (Gillespie & Perry, arXiv:2606.17519, Jun 2026), from a deployed assistant with 110 agents / 584 tools and 1,435 human-labeled utterances: "Routing F1 on under-specified requests drops 16–23 percentage points across models" scaling from 10 to 110 agents. It decomposes this into a retrieval gap and a confusion gap — "even with perfect retrieval, the oracle ceiling drops 10pp". Mitigation: "Embedding-based shortlisting recovers +10–11pp F1 at full scale across all three models and two providers." https://arxiv.org/abs/2606.17519
2. **Multi-agent failures are dominated by design and verification, not model quality.** *Why Do Multi-Agent LLM Systems Fail?* (Cemri et al., arXiv:2503.13657, Mar 2025; rev. Oct 2025) introduces **MAST**, "14 unique modes, clustered into 3 categories" — system design issues, inter-agent misalignment, and task verification — with inter-annotator agreement kappa = 0.88. It notes MAS "performance gains on popular benchmarks are often minimal." https://arxiv.org/abs/2503.13657
3. **Anthropic's cost and applicability figures.** Agents use "4× more tokens than chat interactions, and multi-agent systems use about 15× more tokens than chats." Their multi-agent research system outperformed a single Claude Opus 4 agent by 90.2% on their internal research eval. Good fit: "heavy parallelization, information that exceeds single context windows… numerous complex tools." Poor fit: shared-context/interdependent work and most coding tasks. On delegation: "without detailed task descriptions, agents duplicate work, leave gaps, or fail to find necessary information" — each subagent needs "an objective, an output format, guidance on the tools and sources to use, and clear task boundaries." https://www.anthropic.com/engineering/multi-agent-research-system
4. **The counterweight.** Cognition, *Don't Build Multi-Agents* (Walden Yan, 12 Jun 2025): "Share context, and share full agent traces, not just individual messages" and "Actions carry implicit decisions, and conflicting decisions carry bad results." Recommends single-threaded linear agents, plus a dedicated model that compresses history into key details and decisions. https://cognition.com/blog/dont-build-multi-agents
5. **Subagent return contracts.** Anthropic, *Effective context engineering for AI agents* (29 Sep 2025): a subagent "might explore extensively, using tens of thousands of tokens or more, but returns only a condensed, distilled summary" — on the order of 1,000–2,000 tokens — letting the parent "focus on synthesizing and analyzing the results." Also names compaction and structured note-taking as the persistence primitives. https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents
6. **Cognition partially reversed itself — in CCv3's favour.** *Multi-Agents Are Working Now* (Walden Yan, 22 Apr 2026), the follow-up to source 4: "Our original observations still hold today for parallel-writer swarms… But we've found a narrower class of patterns that do: setups where **multiple agents contribute intelligence to a task while writes stay single-threaded**." Its reviewer finding is counter-intuitive and directly applicable: the generator/reviewer loop "work[s] best when the coding and review agents **do not share any context beforehand**" — a clean-context reviewer reasons backward from the implementation and catches more, because "Context Rot… is a result of models making less intelligent decisions at longer and longer context lengths." https://cognition.com/blog/multi-agents-working
7. **Role specification is a measured lever, not a style preference.** MAST's intervention study (same paper as source 2): "Our intervention studies (Appendix H) show that improving agent role specifications alone yields a **+9.4% success rate increase** for ChatDev with the same user prompt and LLM (GPT-4o)." Its framing: "many MAS failures arise from the challenges in organizational design and agent coordination rather than the limitations of individual agents." https://arxiv.org/html/2503.13657
8. **The harness surface moved underneath us.** Claude Code Agent SDK subagent docs: selection is description-driven ("Claude determines whether to invoke them based on each subagent's `description` field"); isolation is strict ("only its final message returns to the parent"; "the only content you pass from parent to subagent is the Agent tool's prompt string"). `AgentDefinition` now exposes **per-agent `effort`** (`low|medium|high|xhigh|max`), **`skills`** (preload), **`memory`** (`user|project|local`), `maxTurns`, and `background`. Subagents now nest up to three layers by default and run in the background by default (v2.1.198+). Duplicate `name` is a documented load failure. For "dozens to hundreds of agents" it points to the `Workflow` tool rather than turn-by-turn delegation. https://code.claude.com/docs/en/agent-sdk/subagents

The honest summary: the *architecture* remains frontier-aligned, and source 6 strengthens that — CCv3's read-heavy isolated subagents with a single writing orchestrator is exactly the narrow class Cognition now says works. Every gap is a **wiring or calibration** defect — the same failure class this harness keeps hitting (inert off-switch, dead matcher, `agent-error-capture` silent for 161 days). The agent layer's marquee 2026-07 fix joined that list.

## 4. Recommendations

- **R1 — Fix the `agent-recall-injector` floor. ADOPT (highest value, smallest diff).** Replace the single `PROACTIVE_INJECTION_FLOOR = 0.05` with the mode-aware floor its sibling already proved (`HYBRID_FLOOR = 0.01` semantics), and correct the false comment at `:14`. **Bounded, evidence-backed upside: all 56 fires that returned results scored 0.0115–0.0203, i.e. every one clears a 0.01 floor — so this alone moves the agent path from 0% to ~13.5% injection.** Rationale: one constant; a proven reference implementation 40 lines away; closes the gap the last proposal called biggest.
- **R2 — Re-diagnose and ungate `ST-10`. ADOPT.** `BACKLOG.md:63` frames ST-10 as a *budget/latency* problem (`D2b-03`, "0-for-78") and sequences it **after ST-05**. The data splits that into two independent causes: 86.5% of fires returned zero results (consistent with the latency/budget theory — genuinely ST-05's job), but the other 13.5% returned results that were **all discarded by the floor**. So **ST-05 alone cannot fix ST-10** — ship the daemon and injections stay at zero, because the floor is still unreachable. R1 is a prerequisite ST-05 does not supply, and it is not gated on ST-05.
- **R3 — Reclaim the routing surface. ADOPT.** Three concrete moves, cheapest first: (a) move `~/.claude/agents/archive/**` and `_archived/**` out of the discovered tree (they are live agent definitions today, not an archive); (b) resolve the `principal-reviewer` duplicate-`name` collision; (c) control `Explore` with a mechanism rather than prose — a rule that is always in context and losing ground (16.1% → 28.9%) is not an enforcement layer. Rationale: src 1 says roster size costs 16–23pp of routing F1, so shrinking a surface where two-thirds is never selected is the cheapest accuracy available.
- **R4 — Add the multi-agent cost gate + scaling rules. ADOPT (carried from 2026-07-14 R3, still unbuilt).** Encode src 3's 15× figure and its good-fit/poor-fit split into `.claude/rules/proactive-delegation.md`. Rationale: unchanged; still rules-only cost.
- **R5 — Role + output contracts for the top-5 agents. ADOPT (upgraded — now quantified).** Give the five most-spawned agents an explicit "objective / output format / boundaries" block (src 3) and a stated return budget (~1–2k tokens, src 5). MAST measures **+9.4% success from improving role specifications alone** (src 7), which moves this from "cheap hygiene" to the best-evidenced quality lever in the component. It also improves the `description:` text that drives selection, so it compounds with R3.
- **R6 — Embedding-based agent shortlisting. WATCH.** The +10–11pp recovery (src 1) is real but measured on a 110-agent enterprise catalog. R3 shrinks our effective roster first; re-evaluate only if mis-routing persists after that. Building a learned router before deleting six zombie agents is the wrong order.
- **R7 — Per-agent `effort` / `skills` / `memory`. WATCH (upgraded from 2026-07-14 R6).** These fields now exist in `AgentDefinition` (src 8). **Unverified:** whether filesystem `.md` frontmatter honours them — CCv3 is entirely filesystem-based. One spike answers it; if yes, `effort` per agent supersedes the global `effortLevel` limitation.
- **R8 — `SubagentStop` verification pass. WATCH (downgraded from 2026-07-14 R4 ADOPT).** Still 0 registrations and still the unblocker for `ST-01`, but it is a new-hook change in the subsystem with the worst regression history, and R1–R3 deliver more per unit of risk. Sequence it after them.
- **R9 — More agents / new specialist roles. SKIP.** With 18 of ~51 types ever selected and src 1 showing roster size directly costing routing accuracy, adding agents is negative-value right now.
- **R10 — Feeding reviewers the author's context. SKIP (explicitly).** Source 6 measures the opposite: reviewers work best with *no* shared prior context. CCv3's cold-diff reviewers are already correct — do not "improve" them by passing the implementation plan.

**Verification that this actually worked:** re-run the injection query against `agent-recall.jsonl` after ~2 weeks. `kept_after_floor > 0` must be non-zero. That number has been 0 for 415 consecutive fires, so any non-zero value is unambiguous evidence — and if it stays 0 after R1, the diagnosis in §1 is wrong and should be reopened rather than patched around.

**What could go wrong:** (a) lowering the floor injects *weak* matches into every agent spawn — mitigated because the same floor already runs on the main path at 81% injection without complaint, and the sanitizer (`shared/memory-sanitize.ts`) is already wired here, unlike 3 of the 5 main-path injectors (`ST-07`); (b) moving archived agents breaks a workflow that silently depends on a zombie — the `git grep` gate catches it; (c) an edit to this hook regresses a sibling emit — that is exactly what the emit audit is for.

## 6. Benefits

- **Agents stop starting cold.** Every `scout`/`kraken`/`critic` spawn — 415 in three months, ~130/month — currently gets zero benefit from a memory system holding 100+ learnings. R1 turns the harness's "every conversation builds on the last" premise on for the layer doing most of the work. This is the single highest-yield line-change available in the component.
- **A real number replaces a hopeful one.** ST-10 is currently queued behind ST-05 on a diagnosis the data contradicts. Dave gets the fix now instead of after the daemon arc, and avoids shipping ST-05 and finding injections still at zero.
- **Cheaper, more accurate delegation.** Cutting ~6 zombie agents and a name collision shrinks a selection surface where src 1 measures 16–23pp of routing F1 loss from roster growth — and removes the chance of an undefined duplicate-`name` resolution silently swapping a reviewer.
- **A quantified quality lever.** R5's role/output contracts carry a measured +9.4% success uplift (src 7) for what is a docs-only change to five files.
- **Fan-out becomes a decision.** The 15× token multiplier named in a rule keeps Dave off that path unless the task is genuinely breadth-first — real quota savings on a subscription-metered stack.
- **Honest inventory.** `docs/agents/README.md` documents 37 agents; the live surface offers ~51. After R3 those numbers converge, so the README becomes trustworthy again.

## 7. Open questions

1. **Why does the agent path run `--text-only` at all?** `agent-recall-injector.ts:358-360` justifies it as a spawn-time latency budget. But the main path gets 83% results on hybrid vs this path's 13.5% on text-only. If ST-05's warm daemon makes hybrid affordable at spawn (~160–250 ms per `FH-02`), switching mode is worth more than the floor fix — R1 raises injection to ~13.5%, hybrid could take it toward the main path's 81%. **This is the real ST-05 dependency**, and it is a different change from R1.
2. **How should `Explore` actually be controlled?** It is built-in, so it cannot be deleted. Options: a `disallowedTools`/permission-layer deny, or accept that a rule loaded into every session has lost 67 times and is losing faster. Worth asking whether `Explore` is in fact the better tool for those 67 calls and the rule is wrong — the data cannot distinguish "rule ignored" from "rule outdated."
3. **Do filesystem `.md` agents honour `effort` / `skills` / `memory`?** Gates R7 entirely. One spike.
4. **Are the 17 `.json` companions dead or not?** `CURRENT-STATE.md:37` calls them "never executed" (`D7c-01`), but `.claude/scripts/core/claude_spawn.py:278-291` documents loading "Agent configuration from `.claude/agents/*.json`", and `agent-model-selection.md` states the `.json` `model` field is read at spawn. **These cannot both be true.** Resolve before any prune — the 2026-07-14 R2 recommended deleting them on the strength of the "never executed" claim alone.
5. **Is the review family genuinely distinct?** Unchanged from 2026-07-14: `critic`/`judge`/`surveyor`/`liaison`/`principal-reviewer`/`review-agent`, of which only `critic` (16) and `plan-reviewer` (7) register in the census. Still needs an overlap audit before cutting.
