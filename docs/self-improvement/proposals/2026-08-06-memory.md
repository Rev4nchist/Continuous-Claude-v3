**SG-01's stated success criteria are met.** The residual defect the 07-25 pass named is also
confirmed and unchanged: whole-hook p50 is **1,806 ms against a ~136 ms warm design target** — a
live socket probe recorded in BACKLOG FH-02 measured warm daemon recall at ~160–250 ms, so roughly
1.5 s of the 1.8 s is *not* daemon recall compute. Attribution is still impossible from the log:
`total_elapsed_ms` spans the whole hook body (`memory-awareness.ts:468` → `:656`) and there is no
`daemon_ms` field to subtract.

**New defect A — the recall telemetry has no usefulness signal, by construction.** Over the 228
post-fix events:

- `results_count` is **3 in 222 of 228 rows** and 0 in the other 6. It is never 1 or 2, because the
  hook hard-slices `const top = deduped.slice(0, 3)` (`memory-awareness.ts:255`).
- `top_score` (RRF) spans **p10=0.0277 → p50=0.0312 → p90=0.0325**, min 0.0000, max 0.0357. A ~0.005
  spread across the middle 80% carries essentially no discriminative signal.
- The `HYBRID_FLOOR` gate is therefore near-inert: `kept_after_floor` is 3 in 218 of 228 rows.

So the "97.4% hit rate" above means *"the pipeline returned three rows"*, not *"the right memory was
found."* We inject three memories into essentially every qualifying prompt and have **no recorded
signal, anywhere, about whether any of them were relevant or used.** The 27.4% figure in
`docs/system-update/CURRENT-STATE.md:35` has been replaced by a metric that is ~100% by design, not
by an improved one. (QW-06 `10ee124` genuinely fixed the floor/FTS math; the point is that what
replaced it does not measure quality.)

**New defect B — the 2026-07-24 distill-before-store pipeline has produced zero rows.** Query

- Cause: the distiller is invoked **only** on the thinking-block path

  green, and doing nothing, with no telemetry that would say so.*

## 2. Frontier scan

Every arXiv page below was fetched this session and its abstract read; figures are quoted from the
abstract, not paraphrased from a summary.

- **The small-corpus regime is now a named, published finding, and it argues against retrieval
  sophistication at our scale.** ConvoMem (Salesforce, 13 Nov 2025) — *"Convomem Benchmark: Why Your
  First 150 Conversations Don't Need RAG"* — reports "simple full-context approaches achieve 70-82%
  accuracy even on our most challenging multi-message evidence cases, while sophisticated RAG-based
  memory systems like Mem0 achieve only 30-45% when operating on conversation histories under 150
  interactions", and that long context "remains viable with manageable trade-offs up to 150
  conversations" (https://arxiv.org/abs/2511.10523). Our corpus is 685 discrete learnings, not
  conversations, so the threshold does not map directly — but the finding is that **below some scale,
  retrieval machinery underperforms just showing the model the material**, which is the regime we are
  arguably in.
- **Conflict resolution is being pulled out of the LLM into a deterministic stage.** "Reliable
  Post-Retrieval Assembly for Agent Memory: Separating Evidence Extraction from Policy Execution"
  (31 May 2026) argues systems "retrieve relevant evidence yet still fail when answer generation
  entangles semantic filtering, conflict resolution, prior suppression, and output generation in one
  step", and proposes post-retrieval assembly as "a distinct reliability boundary between retrieval
  and answer generation"; it reports 27%/41% multi-hop on MemoryAgentBench v3 FactConsolidation with
  gpt-4o-mini/gpt-4o (https://arxiv.org/abs/2606.01435). Directly relevant to a store with **zero
  recorded supersessions** and a distiller that could write contradicting facts over time.
- **Write-time consolidation remains the converged pattern.** Mem0 (28 Apr 2025) "dynamically
  extracts, consolidates, and retrieves salient information", claiming 26% relative improvement on
  the LLM-as-a-Judge metric over OpenAI, 91% lower p95 latency and >90% token cost savings vs
  full-context on LOCOMO (https://arxiv.org/abs/2504.19413). Note the benchmark is contested — Zep
  published a rebuttal arguing a misconfigured baseline and an unstandardized judge
  (https://blog.getzep.com/lies-damn-lies-statistics-is-mem0-really-sota-in-agent-memory/); vendor
  vs vendor, treat both numbers as marketing-adjacent.
- **Idle-time consolidation has hard numbers.** Sleep-time Compute (Letta/UC Berkeley, 17 Apr 2025)
  reports ~5x reduction in test-time compute for equal accuracy on Stateful GSM-Symbolic and Stateful
  AIME, 13% / 18% accuracy gains respectively, and 2.5x lower average cost per query when amortized
  across related queries (https://arxiv.org/abs/2504.13171).
- **The vendor now ships per-subagent persistent memory.** Claude Code's `memory` field "gives the
  subagent a persistent directory that survives across conversations", with user/project scopes; the
  main conversation's auto memory is explicitly *not* loaded into subagents except in a fork
  (https://code.claude.com/docs/en/sub-agents, https://code.claude.com/docs/en/memory). This is new
  relative to the 07-25 pass, which recorded vendor subagent memory as "also broken/isolated."
- **Vendor memory is file-based with no retrieval primitive — and that is now explicit.** Claude
  Code auto memory is a `MEMORY.md` index plus topic files; "the first 200 lines of `MEMORY.md`, or
  the first 25KB, whichever comes first, are loaded at the start of every conversation", topic files
  load on demand, and an over-limit write returns an error telling Claude to rewrite the index. Files
  written with frontmatter now get a `modified` ISO-8601 timestamp so freshness is visible to the
  model (https://code.claude.com/docs/en/memory). There is no embedding or ranking step anywhere in
  it. CCv3 already runs this layer (`~/.claude/projects/.../memory/MEMORY.md`) alongside pgvector —
  convergent, not a gap.
- **Two-stage retrieve→rerank remains the reference shape, with the reference numbers unchanged.**
  Anthropic's contextual retrieval post: contextual embeddings alone cut top-20 retrieval failure 35%
  (5.7%→3.7%); + contextual BM25, 49% (→2.9%); + reranking, 67% (→1.9%), retrieving top-150 then
  passing top-20 (https://www.anthropic.com/engineering/contextual-retrieval). Note the shape: rerank
  earns its keep over a **150-candidate** pool. Our hybrid arm returns a handful.
- **Reranker sizing.** `bge-reranker-v2-m3` (the model in our dormant flag) is a 568M-param
  cross-encoder distilled from BGE-M3 (https://huggingface.co/BAAI/bge-reranker-v2-m3).
- **Embedding currency.** Qwen3-Embedding (5 Jun 2025) claims leading MTEB multilingual results in
  its technical report (https://arxiv.org/abs/2506.05176). BGE-large-en-v1.5 is no longer near the
  top of open-model leaderboards. **[Speculation]** I could not fetch the live MTEB leaderboard this
  session, so BGE-large's exact current rank is unverified; aggregator blogs are not a citation.
- **Benchmark credibility is contested.** LongMemEval (https://arxiv.org/abs/2410.10813) remains the
  credible long-horizon harness. A public audit claiming a 6.4% corrupted answer key in LoCoMo, and
  that a naive filesystem-search baseline matches sophisticated memory systems, circulated this year
  (https://dev.to/penfieldlabs/we-audited-locomo-64-of-the-answer-key-is-wrong-and-the-judge-accepts-up-to-63-of-intentionally-33lg)
  — **[Speculation]**: a dev.to post, not peer-reviewed, and I did not reproduce it. The direction
  (leaderboard numbers are soft; local per-corpus evals are worth more) is corroborated by the Zep
  rebuttal above and by the 07-25 pass's survey citations.

**Genuinely new since the 07-25 pass:** ConvoMem's small-corpus finding; the vendor's per-subagent
memory field; the post-retrieval-assembly framing of conflict resolution. **Not new:** hybrid+RRF,
cross-encoder rerank, episodic/semantic/procedural taxonomy, contextual retrieval — all unchanged
defaults.

## 4. Recommendations

**R1 — Instrument relevance before building any more retrieval. ADOPT (small, do first).**
This is the pass's central finding. We inject 3 memories on ~every qualifying prompt and log nothing
that distinguishes a good injection from a bad one — `results_count` is 3 by construction
(`memory-awareness.ts:255`) and RRF `top_score` has a ~0.005 interquintile spread. Two cheap
instruments, no architecture change:
(a) log a `daemon_ms` alongside `total_elapsed_ms` so the ~1.5 s residual can be attributed (this is
07-25 R4's unanswered question, still unanswerable today);
(b) record the injected memory ids per event so a later pass can ask "was an injected memory's
content ever echoed, edited, or acted on in the same session" — an offline, retrospective proxy for
usefulness, computed from logs, not a new hot-path call.
Without (b) every future recall verdict on this component stays an opinion.

**R2 — Fix or retire the distill path. ADOPT (small).** 0 of 90 rows in 13 days. Either wire
`distill()` into the path that actually writes (handoff indexing is 81% of current volume), or mark
the feature dormant in `BACKLOG.md` and stop counting it as shipped capability. What is not
acceptable is the current state: a rated-Even capability that has never run, discoverable only by
querying the corpus. Add a one-line counter to the extraction run so "distilled: 0" is visible
without SQL.

**R3 — Run the eval that the 07-25 pass asked for, on a refreshed set. ADOPT (small, unchanged).**
`recall_eval_report.json` still reads 2026-05-21 / `daemon_mode: false`. It now also predates the
`92600ef` project-scope fix. The harness exists with its decision gate written in its own docstring.
Two arms warm (baseline, `--rerank`), plus the ~10-15 new pairs the last pass specified. This is the
only thing that can settle SI-01.

**R4 — Test the null hypothesis at our corpus size. ADOPT (small, new).** ConvoMem
(https://arxiv.org/abs/2511.10523) reports that below ~150 conversations, full context beats
RAG-style memory by a wide margin. We have 685 discrete entries with a 529-char median — roughly
360 KB of text, too much for full context, but the *shape* of the finding demands a third arm in R3's
eval: **hybrid RRF vs rerank vs a naive lexical/recency baseline.** If the naive arm is competitive
at k=5, the correct move is to simplify, not to add a reranker. Cheap to run inside the existing
harness; it is the one experiment that could save an M-sized build.

**R5 — Give one high-value subagent the vendor `memory:` field. ADOPT (small, new).** The vendor now
ships per-subagent persistent memory (https://code.claude.com/docs/en/sub-agents); 0 of our 37 agents
use it. This routes around ST-10 entirely rather than fixing `agent-recall-injector` — the hook that
has yielded 0 recalls for its whole life and is flagged DELICATE. Start with one agent whose value is
cumulative (`critic` or `scout`), user-scoped, and read the file after a week.

**R6 — Provenance tags at store time. ADOPT (small, third carry-over).** Unshipped since 07-12 R5.
The metadata key census shows `tags` on 474 of 685 rows and no layer marker anywhere. Tag writes with
their producing layer; the R2 counter and the R1 relevance analysis both get sharper for free.

**R7 — Supersession / conflict handling. WATCH → promote on evidence.** 0 of 685 rows superseded is
either a healthy corpus or an unused mechanism, and we cannot currently tell which. Trigger: if R1(b)
shows stale or contradicting entries appearing in live top-3 injections, adopt the deterministic
post-retrieval assembly shape (https://arxiv.org/abs/2606.01435) rather than asking the LLM to
resolve conflicts inline. Propose-don't-delete, as before.

**R8 — Sleep-time consolidation. WATCH (unchanged, 4th pass).** Letta's numbers are real
(https://arxiv.org/abs/2504.13171) but the trigger is unchanged: gated behind R7, which is gated
behind R1(b). Do not build it blind.

**R9 — Embedding model swap. WATCH (unchanged).** Becomes a third arm in R3's harness once that runs.
Not before.

**SKIPs re-affirmed (fourth time):** general graph/KG layer — our workload is point lookup, not
multi-hop aggregation; episodic/semantic/procedural store split — no measured gain in the field's own
surveys; replacing pgvector with vendor-native memory — no retrieval primitive
(https://code.claude.com/docs/en/memory), and we already run the file layer alongside.
**New SKIP:** contextual retrieval as described by Anthropic — its gains are measured over a
150-candidate pool of *document chunks* (https://www.anthropic.com/engineering/contextual-retrieval);
our units are already whole, self-contained, human-legible learnings with a median of 529 chars.
There is no chunk to contextualize.

return "the naive baseline is fine", which invalidates work already ratified as SI-01 — that is the
point of running it, and it should be recorded as a legitimate outcome, not re-litigated.

## 6. Benefits

- **Dave finds out whether memory is actually helping.** Today the honest answer is "unknown" —
  97.4% of prompts get three memories injected and nothing anywhere records whether one was right.
  R1 turns the component's core claim into something with evidence behind it, for a day of work.
- **One silently-dead feature gets caught, and a class of them gets a detector.** R2 closes a
  13-day-old no-op that a green ship and three proposals all missed. The distilled-count line is the
  cheap general guard against the recurring "shipped, green, inert" pattern.
- **A build decision either gets made or gets cancelled.** SI-01 has been open across four passes.
  R3+R4 produce the two numbers its own decision gate asks for, plus a naive baseline that could
  retire it outright — the cheapest possible resolution.
- **Sub-agent memory stops being blocked on a DELICATE hook.** R5 is a one-file frontmatter change
  against a vendor primitive that did not exist at the last pass; ST-10's risky path is no longer the
  only path.
- **Latency stops being a mystery number.** R1a attributes the 1.5 s gap between measured warm recall
  (~160–250 ms) and observed whole-hook p50 (1,806 ms), which decides between tuning the daemon and
  moving recall off the per-prompt path entirely.

## 7. Open questions

1. **Is any injected memory ever used?** Unanswerable today. R1b is the first instrument that could
   answer it, and everything downstream (rerank, consolidation, embedding swap) is guesswork until it
   does.
2. **Where do the ~1.5 seconds go?** Open across three passes now. R1a answers it.
3. **Is 685 entries above or below the scale where retrieval beats simpler approaches?** ConvoMem's
   150-conversation threshold does not map cleanly onto 685 discrete learnings; R4 is the local
   answer.
4. **Why did thinking-block extraction stop on 2026-03-05?** Not investigated in this pass — I
   confirmed the absence of rows, not the cause. It may be intentional (a disabled hook), which would
   make R2's answer "retire", not "fix".
5. **Is a zero-supersession corpus healthy or is the mechanism just unused?** 685 rows, 4 exact-dup
   groups, 29% written in the last 30 days. R1b's data decides whether R7 promotes.
6. **Governance carry-over:** the 07-12 flag stands — proposals in this series keep narrowing a
   ratified BACKLOG item (SI-01) without a formal re-ratification step. R4 may now recommend killing
   it outright, which sharpens the question.
